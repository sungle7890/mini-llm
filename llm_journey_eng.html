Building a Mini LLM from Scratch

A day's log of hand-coding everything from the tokenizer to the backpropagation of self-attention, and seeing with my own eyes — through scaling, grokking, and the lottery — the conditions under which learning actually works.

Python 3.14 NumPy only no autograd CPU · a few minutes

Premise

An LLM is really just 4 pieces

  1. Tokenizer — text ↔ numbers. "안녕" → [12, 87]
  2. Model (neural network) — "the tokens so far → probability distribution over the next token." The core is self-attention.
  3. Training — differentiate the gap between prediction and answer (loss) via backpropagation, then nudge in the opposite direction little by little (gradient descent). Repeat thousands to millions of times.
  4. Generation — with the trained model, draw the next token one at a time and string them together.

Below is a log of building these four pieces one by one, by hand. I skipped autograd in order to see what training actually computes.

The journey · 01 → 06

A training pipeline built by hand

01 · Tokenizer — turning text into numbers

The model doesn't know letters, only numbers. Every unique character gets a number.

'아침에 눈을 뜨면' → [176, 258, 189, 1, 50, 215, 1, 85, 119]

02 · Bigram — 'counting' without a neural network

Feel out "a language model = probability of the next character" without any neural network. Just count how many times each character follows the previous one. The loss drops from random 5.62 → 4.03 = something is being 'learned'.

03 · MLP — where 'real training (backpropagation)' shows up

The 4-step training loop appears for the first time: forward pass → loss → backpropagation → update. I implement backpropagation by hand and verify it against numerical differentiation (gradient check) — relative error ~1e-8, passing.

loss: 5.63 (start) → 0.226 (end)   # watching training run with your own eyes

04 · Mini GPT (Transformer)

self-attention + LayerNorm + residual connections, with backpropagation entirely by hand. The full model passes the gradient check. loss 6.04 → 0.29, and it generates Korean sentences.

05 · A magnifying glass on 'one step' of backpropagation

Pick a single weight W[0,1] and trace forward pass → loss → gradient → update by hand:

gradient dL/dW[0,1] = -0.6764        # matches numerical differentiation ✅
after update: loss 1.1284 → 1.0831   # correct-answer probability 32.4% → 33.9%

06 · What a "model file" really is

Save the training result (weights) as an .npz and you can reload it and generate instantly, without retraining. Training + saving 17.7 s → loading + generating 0.11 s.

Experiment 1 · Smoothness

Scaling law — what happens if you add more data?

Train the same model, doubling only the amount of training data each time. The val loss on unseen text comes down smoothly, not off a cliff.

Datatrain lossval lossoverfitting gap
500 chars0.265.325.06
4,000 chars0.872.191.32
16,000 chars1.321.490.17

With little data, the model memorizes everything wholesale (train↓, val↑) — overfitting. With more, it learns the 'rules' and generalizes (gap↓). The "singularity where intelligence suddenly pops into being" is the result of this smooth curve continuing across dozens of orders of magnitude, not a leap at a single point.

Experiment 2 · Abruptness

Grokking — memorizing, then suddenly 'understanding'

Task: (a+b) mod 97. train hits 100% early while val sits at the floor, then jumps sharply at some point — a phase transition from memorization to rule discovery.

# 07: training  val accuracy 0.01 (guessing) → 0.99  (best checkpoint saved)
# 08: validation  pairs 'not seen' in training → 12/12 correct, 98.9% accuracy over all 4705 unseen pairs
         e.g.) 45 + 70 = 18   (actual 115 mod 97 = 18 ✅)

A genuinely abrupt phase transition, in contrast to the smoothness of scaling. This model didn't memorize the answers — it learned the rule, so it can compute even for inputs it has never seen.

An honest observation

This setup (weight decay 1.0) trains unstably, oscillating (collapse↔recovery). So instead of the last one, we save the best point (best checkpoint) — a common practice in the real world too.

Experiment 3 · No signal

The lottery — ML can't beat randomness

Premise

A lottery draw is an independent random event every time, so no model can predict the next numbers any better than chance. The experiment below proves that directly. (For fun + education.)

A · Frequency model — the same 'counting' as 01_bigram

Learn the frequency of past numbers and draw a ticket. The distribution is almost perfectly uniform (no clear bias).

Backtest (last 300 draws): the 'trained' model and random are statistically identical = training gives no edge.

avg white balls matched (of 5)Powerball hit rate
'trained' frequency model0.3610.0374
pure random0.3640.0387
theoretical expectation0.3620.0385

Odds of the jackpot = 1 / 292,201,338. No model can change those odds.

B · Training a neural network on the lottery — it only memorizes, it can't predict

I trained MiniGPT on sequences of lottery white balls (shuffling to remove the sorting pattern → signal 0).

        train loss    val loss   (random floor 4.234)
step 1     4.52         4.61
step 4000  0.65        14.90     # train ↓ (memorizing), val ↑↑ (confidently wrong)
val top-1 hit rate for the next number = 1.30%   (random = 1.45%)

train loss plummets (memorization), but val loss goes above the random floor — because it applies the memorized pattern to unseen draws while being confidently wrong. And the hit rate is identical to guessing.

Conclusion

A model's ability comes down to 'the signal in the data'

It's the same neural network (MiniGPT), yet the data produced completely opposite results.

DataSignalval lossResult
Korean textYes (grammar, words)↓ below floortraining succeeds, generates sentences
Modular additionYes (a rule)↓ via grokkingrule discovered, ~100%
LotteryNone (random)↑ above floormemorizes noise, can't predict

For training to work, the data must contain signal. When it's there, the network extracts the rules and generalizes; when it's not, no matter how big the model or how long you train, it just memorizes noise and stops there. A model can never conjure a pattern that isn't in the data. GPT is this same principle scaled up — characters→BPE, many stacked blocks and multi-head attention, vast data, GPUs, and alignment (RLHF).
